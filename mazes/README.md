# 🌀 Mazes - Reinforcement Learning Experiments

This repository contains implementations and experiments related to **Reinforcement Learning (RL)** in maze-like environments.  
It includes Python modules, Jupyter notebooks, and generated figures inspired by examples from Sutton & Barto's *Reinforcement Learning: An Introduction*.

## 📒 Notebooks

- **`changing_maze.ipynb`** – Experiments with environments that change over time.  
- **`dyna_maze.ipynb`** – Implementation of the **Dyna-Q** algorithm for planning and learning.  
- **`prioritized_sweeping.ipynb`** – Experiments with **prioritized sweeping** to speed up learning.  

Run notebooks using Jupyter:
```bash
jupyter notebook notebooks/
```

## 📊 Images

Each notebook saves its figures into `generated_images/`.  
Descriptions below explain exactly what each plot shows and which notebook/parameters produce it:

### Learning curves  
*(from `notebooks/dyna_maze.ipynb`)*  

- **What it shows:** Steps per episode (y-axis) vs episode number (x-axis) for three Dyna agents with planning steps `n = {0, 5, 50}`.  
- **Averaging:** Data averaged over `runs = 10`.  
- **Key parameters:** `planning_steps` (0, 5, 50), `episodes = 50`, `alpha` (step size), `gamma` (discount).  
- **Interpretation:** Fewer steps means faster learning. A dashed line at `y = 14` marks the relaxed optimal path length. Larger `n` speeds up learning.

### Backups until optimal  
*(from `notebooks/prioritized_sweeping.ipynb`)*  

- **What it shows:** Number of backups (planning updates) required to reach the optimal solution vs maze resolution factor (`x = 1..K`).  
- **Comparison:** Prioritized Sweeping vs Dyna-Q.  
- **Experiment setup:** `extend_maze(factor)`, `runs = 5`. For Dyna-Q, backups adjusted (`backups[1,:] *= planning_steps + 1`).  
- **Axis scaling:** Y-axis log scale (to highlight differences).  
- **Interpretation:** Prioritized Sweeping usually needs far fewer backups as maze size grows.

### Blocking-maze cumulative reward  
*(from `notebooks/changing_maze.ipynb`)*  

- **What it shows:** Average cumulative reward over time for **Dyna-Q** vs **Dyna-Q+**.  
- **Environment:** A short route is blocked at `obstacle_switch_time = 1000`.  
- **Settings:** `max_steps = 3000`, `runs = 20`, `planning_steps = 10`, small `time_weight` for Dyna-Q+.  
- **Interpretation:** Both algorithms learn the short path, lose reward when it’s blocked, then recover. Dyna-Q+ recovers faster due to its exploration-encouraging model.

###  Shortcut-maze cumulative reward  
*(from `notebooks/changing_maze.ipynb`)*  

- **What it shows:** Average cumulative reward over time for **Dyna-Q** vs **Dyna-Q+**.  
- **Environment:** A shortcut opens at `obstacle_switch_time = 3000`.  
- **Settings:** `max_steps = 6000`, `runs = 5`, `planning_steps = 50`, higher `time_weight` for Dyna-Q+.  
- **Interpretation:** Dyna-Q can fail to discover the shortcut due to its static model, while Dyna-Q+ detects and exploits the new path sooner.
